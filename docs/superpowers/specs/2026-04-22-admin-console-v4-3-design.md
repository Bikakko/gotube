# GoTube V4.3.0 管理后台体验重做设计

## 1. 目标

V4.1 完成了后台信息架构和功能边界重整，V4.3.0 不再继续扩大后台能力范围，而是集中解决“难用”和“粗糙”这两个问题。

这一轮的目标不是增加更多功能，而是把现有后台整理成更顺手、更稳定、更统一的管理工作台：

1. 视觉风格向首页月夜风格靠近，但保持后台应有的克制和专业感。
2. 卡片、工具栏、弹窗、表单、状态标签统一成同一套材质语言。
3. 全局媒体页、用户页、系统页都要更容易扫读，减少“按钮堆”和“信息糊成一片”的问题。
4. 页面提示文案从临时性提示升级为正式产品文案。
5. 移动端可用性必须纳入本轮设计，而不是等桌面完成后再补。

## 2. 本轮范围

本轮重做坚持两个边界：

1. 不重做后台一级信息架构，继续保留：
   - 概览
   - 全局媒体
   - 用户
   - 邀请码
   - 系统
2. 不引入大型动态背景或首页级氛围特效。后台与首页共享的是材质和色彩语言，不共享场景化表现。

换句话说，V4.3.0 是“后台体验重做”，不是“后台第二次架构重做”，也不是“把首页整套视觉搬进后台”。

## 3. 设计原则

### 3.1 信息卡优先，不再把卡片做成操作面板

后台媒体卡片继续保留缩略图，因为缩略图是管理效率的一部分。但卡片的职责要从“承载大量按钮”收口到“高效识别媒体信息”。

卡片应该首先帮助管理员回答：

- 这是什么媒体
- 是否值得点开
- 当前归属和状态是什么

而不是一眼先看到一排动作按钮。

### 3.2 风格向首页靠近，但克制

后台应抽取首页的三个优点：

- 深夜蓝黑的底色层次
- 月白高光与柔和边缘光
- 半透明、偏冷的壳层材质

但后台不应引入首页那种月亮、流云、星空和场景化动效。后台的高级感来自秩序、材质和层次，不来自氛围特效堆叠。

### 3.3 页面提示文字要像正式产品，而不是临时调试信息

本轮所有用户可见提示都应遵循统一原则：

- 语义明确
- 不口语化凑数
- 不写开发者心智里的过程描述
- 不把错误原因模糊成“失败了，请重试”这一类弱提示

尤其是：

- 空状态提示
- 复制成功/失败提示
- 删除确认提示
- 分享状态提示
- Cookie、健康检查和系统诊断提示

### 3.4 移动端不是缩小版桌面

后台必须对手机用户友好，但不要求在手机上完全复制桌面管理效率。设计目标是：

- 顶部导航可横向滚动且易点击
- 卡片和表格不溢出
- 工具栏分行后仍有可读顺序
- 弹窗在窄屏下仍可操作
- 危险操作和关键操作仍然容易区分

移动端优先保证“能看清、能点准、能完成核心操作”，不追求桌面同密度。

## 4. 视觉系统

### 4.1 色彩

主色系改为月夜工作台风格：

- 页面底色：深夜蓝黑，而非纯黑
- 面板底色：冷灰蓝半透明面板
- 分割边缘：低对比柔和描边
- 高光颜色：月白、冷青
- 危险色：保留红色，仅用于删除、停用、不可逆操作

这意味着红色不再承担“品牌主色”职责，而退回到风险提示色。

### 4.2 材质

后台统一使用“轻玻璃工作台”材质：

- 面板有轻微透明度
- 边缘不是硬直线，而是柔和发光边
- 阴影不厚重，重点在层次分离
- 弹窗、卡片、工具栏使用同一套材质语言

### 4.3 圆角和边界

卡片、工具栏、弹窗和按钮统一使用更圆润的圆角，不再保留旧后台那种偏硬的矩形边界。圆角要与首页相册卡保有同一家族感，但更内敛。

## 5. 页面级设计

## 5.1 顶部导航

顶部导航继续保留，但要从“功能切换条”升级为“工作台头部”：

- 品牌区弱化，不抢占空间
- 当前视图高亮更清楚
- 用户摘要收口成简洁信息块
- 横向滚动在手机端继续保留
- 头部高度和内边距统一，避免旧导航和新面板脱节

## 5.2 全局媒体页

这是本轮第一优先级页面。

### 卡片结构

每张媒体卡片分成四层：

1. 缩略图层
2. 标题与核心摘要层
3. 资产状态层
4. 主操作层

卡片内只保留最常用的主操作；次要操作进入详情弹窗或次级入口。目标是避免“一张卡就是一整套工具栏”。

### 工具栏

筛选区重做成工具栏，而不是多个零散控件拼起来的表单带。工具栏需要做到：

- 主筛选项一眼可扫
- 搜索框有清晰主次
- 分页大小切换与筛选保持统一语言
- 窄屏下自动换行，但阅读顺序不乱

### 详情弹窗

详情弹窗继续保留，但需要在视觉和内容层次上更稳：

- 概要信息优先
- 拥有者列表和来源列表明确分段
- 展开/收起逻辑继续保留
- 状态标签和关键信息要更规整

## 5.3 用户页

用户页目标是“更像用户管理界面”，而不是“后台里另一种杂糅页面”。

重点改动：

- 搜索条正式化
- 用户状态、角色、容量使用统一状态标签
- 行内操作数量收口
- “查看视频库”入口清晰可见
- 用户视频库弹窗继续保留，但样式与媒体详情统一

## 5.4 系统页

系统页改造成状态面板，不再只是把不同模块堆到一起。

应至少分成三个区块：

1. 运行状态
2. Cookie 状态
3. 诊断与检查结果

每个区块内部要有明确的正常/异常/需处理状态，不依赖大量文字让管理员自己猜。

## 5.5 邀请码页

邀请码页优先做视觉接入，不单独做复杂交互重写。重点是让它与新的工具栏、按钮、表格/卡片样式一致，不再像外挂模块。

## 6. 文案规范

本轮所有提示文案统一遵循以下规则：

1. 成功提示：直接说明结果，例如“分享链接已复制”“已删除该用户的视频库条目”。
2. 失败提示：指出失败对象和可理解原因，例如“分享链接复制失败，请手动复制”。
3. 空状态提示：用一句话说明当前没有什么，以及下一步可以做什么。
4. 删除确认：明确范围和后果，避免模糊表达。
5. 系统状态：优先给状态判断，再给原因或建议。

文案不使用临时性措辞，例如：

- “操作成功”
- “失败了”
- “请重试”
- “没有数据”

除非它们和更具体的信息组合使用。

## 7. 移动端策略

### 7.1 顶部导航

- 支持横向滑动
- 按钮高度与点击区域增大
- 当前标签在窄屏下仍然容易识别

### 7.2 媒体卡片

- 卡片在手机端保持缩略图可见
- 信息密度低于桌面
- 操作按钮数量压缩，避免拥挤

### 7.3 工具栏

- 自动换行
- 搜索框和主筛选优先显示
- 次级筛选不抢占第一行核心区域

### 7.4 弹窗

- 宽度接近全屏但保留边距
- 内容区滚动，页头和关闭入口稳定
- 主操作按钮不挤成不可点击的小块

## 8. 实施顺序

1. 建立后台新的视觉 token 和基础样式
2. 重做顶部导航与公共面板/按钮/表单/弹窗
3. 重做全局媒体页
4. 重做用户页
5. 接入邀请码页样式
6. 重做系统页
7. 统一文案并做移动端回归

## 9. 验收标准

V4.3.0 完成后，应满足以下标准：

1. 后台与首页在视觉上属于同一产品，但后台更克制。
2. 全局媒体页一屏可扫，卡片不再像按钮堆。
3. 用户页更像管理界面，搜索和视频库入口更清楚。
4. 系统页能一眼看出状态，不必通读整页。
5. 用户可见提示文案正式、稳定，不再带临时性语气。
6. 手机端可完成导航切换、媒体查看、用户查看和系统检查等核心操作。
