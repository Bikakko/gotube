# 任务 21：用户管理表布局与 `wk.sh` 编码修复

日期：2026-04-29

## 背景

- 用户管理页中，`角色`、`状态` 等短列被长账号和昵称挤压，视觉上接近竖排。
- `wk.sh` 在 `4.5.1` 版本更新后出现中文乱码。

## 根因

### 1. 用户管理页布局

- 新增 `昵称` 后，原有 `ID / 账号 / 昵称 / 角色` 分列方案已经不适合继续扩展。
- 问题不只是长文本撑宽，而是身份信息本身被拆得过散，导致表格列数过多、短列承压。
- 根因应按“信息重组”处理，而不是继续单纯压宽度。

### 2. `wk.sh` 乱码

- 文件内容本体已经被错误重编码，不是终端显示问题。
- 直接原因是对含中文的 shell 脚本执行了整文件读取再整体写回，导致 UTF-8 中文被错误解码并重新保存。

## 修复

### 用户管理页

- 保留 `ID` 作为第一列，继续承担后台唯一标识作用。
- 将 `账号 / 昵称 / 角色` 合并为单个 `用户` 列。
- `用户` 列内部改为身份卡：
  - 第一行：昵称
  - 第二行：账号
  - 第三行：角色标签与辅助标记
- 身份卡整体带角色语义底色：
  - 管理员：偏金
  - 普通用户：偏蓝
- `状态`、`视频数`、`容量`、`最后登录`、`操作` 保持独立列。
- 表格保留固定布局与横向滚动兜底，但不再依赖“把所有字段拆成细列”来组织信息。

### `wk.sh`

- 以 `4.5.0` 的最后正常版本为基线，恢复完整中文内容。
- 仅保留 `4.5.1` 所需版本号更新，不再沿用乱码文件。

### 防回归约束

- 将“禁止整文件重写含中文脚本/配置/文档，优先局部补丁修改”的规则写入项目 `AGENTS.md`。

## 验证计划

- `node --check www/admin/js/users.js`
- 前端构建
- shell 语法检查：`wk.sh`
