# GoTube v4.11.0 操作说明

本文档适用于自托管运行与日常维护，配置统一通过项目根目录的 `.env` 文件进行管理。

---

## 一、 快速开始

### 1.1 服务启动与停止

- **开发模式**：
  - Windows: `.\dev.bat`
  - Linux/macOS: `./dev.sh`
- **生产模式**（部署为 Linux 后台服务）：
  - ⚠ 已接入 systemd 托管时，启停一律：`systemctl start/stop/restart gotube`（参见 [systemd 部署指南](SYSTEMD-SERVICE.md)）
  - 非 systemd 部署才用：启动 `./gotube.sh start`、重启 `./gotube.sh restart`
  - 查看状态：`./gotube.sh status`（两种部署方式均适用）
  - 维护命令：`./gotube.sh upgrade` / `doctor`（不受 systemd 限制）

### 1.2 访问入口

- **公开相册伪装首页**：`http://your-server-ip:8000/`
- **隐藏下载页**：`http://your-server-ip:8000/{GOTUBE_HIDDEN_PATH}`（例如 `/7777`）
- **管理后台入口**：`http://your-server-ip:8000/{GOTUBE_HIDDEN_PATH}/admin`

## 二、 核心配置管理 (`.env`)

修改 `.env` 后需重启服务生效：

| 配置项 | 说明 | 示例/默认值 |
|---|---|---|
| `GOTUBE_HOST` | 服务监听 IP | `0.0.0.0` |
| `GOTUBE_PORT` | 服务端口 | `8000` |
| `GOTUBE_HIDDEN_PATH` | 下载页/后台弱隐藏路径 | `7777` |
| `GOTUBE_MAX_CONCURRENT` | 全局最大并发下载任务数 | `5` |
| `GOTUBE_MAX_DOWNLOADS_PER_USER` | 单用户/会话最大同时下载数（0=不限制） | `1` |
| `GOTUBE_DOWNLOAD_DIR` | 下载视频存储目录 | `./downloads` |
| `GOTUBE_COOKIES_FILE` | 浏览器 Cookies 凭据路径 | `./data/cookies.txt` |
| `GOTUBE_ADMINS` | 初始管理员账号密码列表 | `admin:your_password` |

## 三、 用户与权限说明

### 3.1 账号体系与注册门控
1. **管理员账号**：启动时自动根据 `.env` 中的 `GOTUBE_ADMINS` 同步创建，支持在后台修改密码。
2. **注册与门控**：普通用户注册需要在后台管理界面开启注册邀请码；注册成功后自动保持登录状态。

### 3.2 邀请码与存储配额 (v4.10.0)
- 在管理后台 `/admin` 的“邀请码”页面可生成注册码。
- 生成时可设定该邀请码注册账号的**存储空间配额（MB/GB）**。
- 生成后支持明文查看与一键复制。

## 四、 安装与升级

### 4.1 一键安装（新机器）
方式一（推荐，一行命令）：
```bash
curl -fsSL https://raw.githubusercontent.com/Bikakko/gotube/master/scripts/install.sh | bash
```
方式二（克隆后执行）：
```bash
git clone https://github.com/Bikakko/gotube.git
cd gotube && ./scripts/install.sh
```
脚本自动完成：系统依赖安装（git/python3/ffmpeg/nodejs）→ 克隆代码 → 生成 `.env` 初始配置（含随机管理员密码）→ 初始化虚拟环境与前端构建。安装完成后执行 `./gotube.sh start` 启动服务。

可通过环境变量定制：`GOTUBE_REPO_URL`（仓库地址，fork 可覆盖）、`GOTUBE_BRANCH`（分支）、`GOTUBE_INSTALL_DIR`（安装目录，默认 `./gotube`）。

### 4.2 升级（已部署环境）
方式一（推荐，项目目录内执行）：
```bash
./gotube.sh upgrade
```
升级流程：
1. **数据库备份**：升级前自动对 SQLite 做一次 `VACUUM INTO` 冷备（存入 `databackups/`）；
2. **拉取代码**：`git pull --ff-only`，若存在本地未提交改动会中止升级并提示处理；
3. **更新依赖**：按 `requirements.txt` 更新 Python 依赖；
4. **重建前端**：仅当 `.env` 中 `GOTUBE_BUILD_FRONTEND=1` 时重新编译；
5. **更新 yt-dlp**：升级到最新版；
6. **自动重启**：若升级前服务在运行，完成后自动重启生效。

方式二：重跑一键安装脚本（保留 `.env`，拉取最新代码并重新初始化环境）：
```bash
curl -fsSL https://raw.githubusercontent.com/Bikakko/gotube/master/scripts/install.sh | bash
```

### 4.3 单独更新下载引擎 (yt-dlp)
当部分平台（YouTube、Twitter、B 站）出现解析变动或下载报错时，可不动代码、单独升级 `yt-dlp`：
```bash
./gotube.sh update
./gotube.sh restart          # 非 systemd 部署
# systemd 托管环境改用: systemctl restart gotube
```

### 4.4 数据库自动备份
- 系统应用内置每天自动对 SQLite 数据库做冷备（`VACUUM INTO` 机制），备份文件保存在 `databackups/` 目录下，默认保留最新 3 份。

### 4.5 Cookies 管理
- 用于下载高画质或需登录权限的视频。可在后台“Cookie 管理”选项卡直接上传/更新 Netscape 格式的 `cookies.txt` 文件。

## 五、 排障指引

1. **缺失 FFmpeg 提示**：确保系统或 Python 虚拟环境已包含 ffmpeg 命令行工具。
2. **连接超时 / 429 限制**：检查服务器网络连接，或更新 Cookies 凭据与 yt-dlp 引擎。
3. **服务状态自检**：运行 `./gotube.sh doctor` 快速检查运行环境与路径依赖。
